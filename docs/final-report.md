# Итоговый отчёт: Kokoro Reader

Исполнитель: Maryna Maksimava. Руководитель, период, группа: *Sergei Audeychik*.
Тип проекта: гибридный (продуктовая часть + эксперимент). Рабочее название: «Kokoro Reader» — озвучка документов
в Telegram с расчётами на устройстве пользователя / *Kokoro Reader: On-Device Document Narration in Telegram*.

## 1. Цель и результат

**Цель.** Бесплатно и быстро слушать документы вместо чтения, с речью заметно естественнее классических
синтезаторов.

**Результат.** Работающий прототип из двух частей:

- **Mini App** (веб-страница на GitHub Pages, открывается в браузере или внутри Telegram): принимает `.txt`, `.md`,
  `.pdf`, озвучивает на устройстве пользователя, подсвечивает читаемое предложение, делает паузы на абзацах и
  заголовках. Адрес: https://maryna-maksimava.github.io/Internship_practice/miniapp/
- **Telegram-бот** (работает на компьютере владельца): принимает файл или текст, озвучивает на сервере, показывает
  индикатор прогресса, отвечает аудиофайлом. Доступ по списку Telegram-ID.

## 2. Что сделано

| Этап | Итог |
|---|---|
| Выбор движка | сравнили eSpeak NG, Piper и Kokoro-82M по слуху и по измерениям; выбран Kokoro |
| Продукт | бот, Mini App, поддержка PDF, паузы, подсветка предложения, индикатор прогресса |
| Подготовка текста | склейка строк PDF, заголовки, замена времени «7:30» на слова |
| Качество кода | тесты (Python и JS), CI на GitHub Actions, общий набор эталонных случаев |
| Эксперимент | 22 предложения, 4 системы, круговая проверка через Whisper, оценка на слух (24 клипа вслепую) |
| Документы | паспорт, архитектура, AGENTS.md, task briefs, ограничения, роли, evidence, отчёты |

## 3. Результаты эксперимента

| Система | WER | Скорость, × реального времени | Естественность 1–5 (слух) |
|---|---|---|---|
| eSpeak NG (baseline) | 12,5% | 57,0 | 1,00 |
| Piper | 1,8% | 25,4 | 3,17 |
| Kokoro без подготовки текста | 3,6% | 3,2 | 4,67 |
| Kokoro с подготовкой текста | 0,4% | 3,2 | 5,00 |

Главные выводы:

1. Kokoro даёт лучшую естественность из бесплатных вариантов; цена — скорость (около 3× реального времени на CPU).
2. Подготовка текста на выражениях времени снижает WER с 17,0% до 2,1% и убирает паузу на двоеточии.
3. Сокращение «St.» читалось как «Elmsent»; найдено экспериментом и исправлено, но на том же наборе, поэтому это не независимая проверка. Другие сокращения (Ave., Rd.) не обработаны.

Подробности: [evaluation-report.md](evaluation-report.md), [evidence.md](evidence.md).

## 4. Проверки

- Тесты: 18 Python-тестов и JS-тест логики Mini App.
- CI (GitHub Actions): оба job (`python`, `miniapp`) зелёные на последнем коммите.
- Демо `python demo/run_demo.py`: 30,4 с аудио, 3,3× реального времени.
- Воспроизведение: [reproduction.md](reproduction.md).

## 5. Ограничения

Полный список: [limitations.md](limitations.md). Главные:

- скорость на телефоне не измерена, в WASM медленно, WebGPU на телефоне давал искажённый звук;
- бот работает только пока включён компьютер владельца;
- нет OCR для сканов PDF, только английский текст, только `.txt`, `.md`, `.pdf`;
- оценка естественности выполнена одним человеком (24 клипа), отзывы других пользователей не собирались;
- шаги README не проверены на чистой машине.

## 6. Роль AI-агента и человека

Код, тесты и документы написаны с помощью AI-агента (Claude Code). Человек ставил цели, принимал решения, создавал
бота и репозиторий, проверял на реальном телефоне, находил ошибки и оценил звук на слух. Подробно:
[agent-human-roles.md](agent-human-roles.md), [agent-worklog.md](agent-worklog.md), [contribution.md](contribution.md).
Ошибки агента, обнаруженные по ходу работы, перечислены в журнале.

## 7. Затраты и ресурсы

Платных облачных ресурсов нет: GitHub, GitHub Pages и Actions бесплатны, модель и библиотеки открыты, бот работает на
компьютере владельца. План остановки или продолжения: [cloud-resources.md](cloud-resources.md).
